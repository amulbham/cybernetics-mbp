# Roadmap

Things flagged during past work but deliberately not done yet, plus open questions. Not date-ordered — roughly grouped by how soon they matter. Move an item to `CHANGELOG.md` (with a real date) once it ships; delete it from here.

## Content-shaped (grow the corpus, these activate on their own)

- **Related-research module** (`RelatedResearch.astro`) is fully built and correct, but won't visibly show anything until at least two entries share a pillar (papers only) or a tag — right now there are 2 papers (different pillars) and 1 essay with zero tag overlap between any of them, so it's still empty everywhere by construction. Nothing to build; it activates naturally as more content gets published.
- **Tag governance**: a hard `z.enum()` on tags was considered and rejected as disproportionate for a solo-author site (see `CHANGELOG.md` 2026-08-14). A casing rule *was* decided 2026-08-24 (sentence case, with a paper's own coined/named terms excepted as proper nouns — documented in `AGENTS.md`) and enforced by the content-manager skill going forward; what's still open is a thin-content generation threshold for `/tags/[tag]/` pages, which would currently delete every existing tag page (each has a count of exactly 1). Revisit once there's actual tag overlap to threshold against — check current counts before picking a number, the way the TOC threshold was picked from real data rather than guessed.
- **Two of five pillars have a published paper** — `policy-systems` (the FAFSA paper) and `cybernetics` (the Invariants paper). `ai-systems`, `seo-architecture`, and `systems-architecture` currently have zero — confirmed `research/[category]/index.astro` and `research/index.astro` both handle this gracefully for pillars (no page/section generated for a pillar with no papers, not an empty broken section — `essays`/`memos` are the deliberate exception, see `AGENTS.md` → "Categories/URLs"; the homepage pillar grid is a further deliberate exception on top of that, showing all 5 unconditionally as navigation). Fills in naturally as real papers get added to those pillars.

## Waiting on the corpus, not on work

- **Research relations (Sprint 7)** — 7.1–7.4 shipped the contract, the first live row (`three-sos--invariants`, `applies`), and its accepted placement decision. **7.5 (2026-09-01) shipped the renderer**: `rehype-research-links.mjs` renders exactly that one decision — Three SOS's §1 now carries one `<a>` to Invariants, and nothing else on the site changed. Real gotcha hit and fixed while building it: `getEntry('astro:content')` as originally specced doesn't resolve from inside a rehype plugin (a Vite virtual module, unreachable from this execution context) — resolved by reading the target's frontmatter directly and calling the real `canonicalPath()`, never a hand-built string; see `CONTENT-MODULES.md`. A second, more consequential gotcha: Astro's content-layer glob loader swallows a per-entry render error and lets `astro build` exit 0 anyway, so a genuinely broken accepted row was silently shipping a page with its Introduction section missing. Fixed with `scripts/validate-research-links.mjs`, now the first step of `npm run build` — the same pipeline, run standalone outside Astro's try/catch, so the same failure is a real non-zero exit. Pangram → FAFSA `converges_with` stays unadded until its own source entry exists. **7.6 next: QA** on what 7.5 shipped — not new rows, not new capability. See `CONTENT-MODULES.md` → "New: research relations" and `PUBLISHING.md` §7.

## Polish, not urgent

- **Content-detail pass** (next editorial sprint, flagged while writing `PUBLISHING.md` 2026-08-26): the Invariants paper's §4 pull-quote and Counterpoint currently sit stacked right next to each other; the frontier essay's "Frontier is the floor" Counterpoint and Key idea read as a cluster rather than two separated turning points. Neither is wrong, both are worth a second look once there's time for a pure editorial pass rather than a placement sprint. While at it: check across all three published pieces for any restated sentence that now exists twice at full length instead of as a genuine restatement.
- **Radius tighten to 4/8/12** (currently 6/10/16) — floated as an option during the Signal visual pass, deliberately not done; only worth reopening after a real reason to, not on its own.
- **`.table-container` still uses `background: var(--bg)`, not `--bg-raised`**, despite being conceptually elevated chrome like a card (see `design-system/tokens.md`'s "Known inconsistency" note — recorded there in detail, not repeated here).
- **Keystatic** — if ever added, it's an authoring layer on top of the *same* collection/schema/grammar/renderer, not a parallel content system. Not currently planned, just the constraint if it ever comes up.
- **Research graph / concept-link UI** — the `{#slug}` ids research primitives can optionally carry (`CONTENT-MODULES.md`) are reserved for this and read by nothing today. See "Waiting on the corpus, not on work" above for the relation-registry work this now depends on.
- **The favicon/logo is still a raster export, not a real vector.** Replaced twice in one day (2026-08-24): first with the design system's serif "AB"+dots monogram, then hours later with a cleaner geometric-ligature "AB" mark the user preferred, which also restored genuine dark-mode reactivity (`favicon.svg`/`favicon-dark.svg` + `favicon-32x32.png`/`-dark.png`, swapped via `media="(prefers-color-scheme: ...)"`, matching what the original pre-monogram favicon could do) — so the reactivity regression flagged in this item's original wording is resolved. What's left is real: it's still a raster PNG embed, not a hand-traced `<path>`, and the flat two-tone geometry of the new mark would likely trace cleanly if this becomes worth doing. Not done here — out of scope for a design-system alignment pass.
- OG images (`src/pages/open-graph/[...route].ts`) use `astro-og-canvas`'s default font (Noto Sans, fetched from Fontsource at build time), not the site's actual brand fonts. Could load Atkinson/IBM Plex Mono into the OG image generator instead for a more on-brand social-card look.
- Pagefind is on the "Default UI" (`pagefind-ui.js`) — functional, and Pagefind's own build output explicitly says it's still supported, but their docs now recommend the newer "Component UI" (a proper search modal, better accessibility/customization) for new integrations. Worth revisiting if search becomes a bigger part of the site.
- Recurring `npm warn allow-scripts` about `esbuild`'s postinstall script not being covered by an `allowScripts` entry. Never investigated whether this matters for this project; builds have succeeded regardless every time.
- `citation` markup on `ScholarlyArticle` — the financial-aid paper has 35 real references now rendered via the `rehype-references` transform (see `AGENTS.md`), but schema.org's `citation` property could structure each one individually in JSON-LD too. Real parsing/markup work per reference, not a quick addition — flagged as existing, not proposed for the near term.
- **Footnotes/sidenotes** — a proposed remark/rehype transform for Markdown `[^1]` footnote syntax, with progressive-enhancement UI (right-margin sidenotes on wide screens ≥1400px, hover/focus tooltips on medium screens, native tap-jump fallback on mobile). Deliberately deferred out of the 2026-08-18 admonitions/scroll-spy/table-wrap sprint: **no paper currently uses `[^1]` syntax anywhere**, so there's nothing real to build or verify against yet (the same discipline that set the TOC threshold and the References transform's scope from measured content, not guesses). It's also meaningfully riskier than the other transforms in that batch — real position math for the sidenote layout, resize handling, and (given this project's history with `ClientRouter`) a genuine risk of a scroll-spy-caliber View Transitions gotcha. Scope it properly once a paper actually needs a footnote.
