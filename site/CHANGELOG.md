## 2026-09-04 (later) — Sprint 9.3 fix: commit-message quoting broke the deploy step

Found live, during the first real push-triggered test of Path B after secrets (9.1) and a successful `workflow_dispatch` (9.2): a real GitHub Actions bug, not a Cloudflare-side problem. `.github/workflows/deploy-pages.yml`'s deploy step built `--commit-message="${{ github.event.head_commit.message || ... }}"` directly inside a `run: |` block — but `${{ }}` expressions are spliced into the script as raw text *before* bash parses the line. A commit message containing an embedded `"..."` phrase closes that quoted string early; everything after becomes bogus extra shell tokens. Confirmed exactly via the failing job's own log: `wrangler`'s error was `Unknown arguments: from, GitHub... preview deploy, and that the` — a literal fragment of that push's commit body (which read, in part, `native "Building from GitHub..." preview deploy`). Every commit message on this repo before that one happened to be quote-free, so this was latent since Sprint 8.2 and never fired until 9.3's own test commit tripped it.

**Fixed the standard way** (GitHub's own security-hardening guidance for any dynamic/untrusted `${{ }}` value used inside `run:`): pass it through an intermediate `env:` var (`COMMIT_MESSAGE`), reference it as a shell variable (`"$COMMIT_MESSAGE"`) instead of splicing the raw expression into the script text. Bash doesn't re-parse for quote characters inside an already-double-quoted variable expansion, so embedded quotes in the value are inert.

**Verified locally before pushing**, not assumed: reproduced the exact failure with the real commit-message text via `eval` (the old direct-interpolation pattern split into 3 shell arguments, reproducing the identical `Unknown arguments: from, GitHub...` shape), then confirmed the `env:`-var pattern collapses back to exactly 1 argument with the embedded quotes preserved intact.

Diff is one workflow file. No other Sprint 9.0 code, docs, secrets, or dashboard settings touched.

- Manifest entry + route sanity (a malformed source shows up as its own clear message, not a downstream 404).
- `index.html` and same-directory `paper.pdf` both exist.

**A real deadlock found and fixed, not just a slow build.** The first working version used `execFileSync` to run Vivliostyle — a *synchronous, blocking* call. Since this script's own static server runs in the same Node process, `execFileSync` freezes the entire event loop for as long as the child process runs, including the server that child process needs to fetch its own assets from. The result: a genuine deadlock, not merely a slow one. FAFSA (by far the largest paper — 12 tables, 50 citations, 11 primitives) reliably reproduced it, timing out at whatever `--timeout` was configured (300s, then 900s) no matter how high, because the server could never answer a single request while frozen waiting on the very process it was blocking. Smaller papers (Invariants, Three SOS) sometimes got lucky — evidently enough loaded in the brief pre-freeze window — masking the bug until FAFSA was tested, which it hadn't been in 8.0 or 8.1. Diagnosed by elimination, each hypothesis tested directly rather than assumed: ruled out `npx` resolution (switching to a direct `node cli.js` invocation didn't help — same deadlock, since it was still `execFileSync`), ruled out the static-server implementation itself (swapping a hand-rolled `http.Server` for `sirv` — the same package `astro preview` itself uses, added as a real pinned devDependency — didn't help either), ruled out the transient copy being corrupt (an isolated test serving the exact same absolutized copy from a *separate* process succeeded immediately). The one variable that mattered: running the server and the child process in the same event loop at all. Fixed by replacing `execFileSync` with `spawn`, awaited via its `close` event — the server stays responsive throughout. All three papers then typeset successfully in one run with no timeout.

**`@vivliostyle/cli` pinned at the exact `11.2.0` proven in Sprint 8.0**, as a real devDependency (not `npx @vivliostyle/cli@latest`, not a global install) — `package-lock.json` committed. Invoked as `node node_modules/@vivliostyle/cli/dist/cli.js build ...` directly, never through `npx`.

## 2026-08-19 — Automatic inline citation linking

Built `rehype-citation-links.mjs`, turning plain-text `(Bennett, 1987)` into `<a href="#ref-1">`. 1. A generic capitalized-phrase regex for the narrative shape unsafely captured entire sentences (`"As documented in Macartney et al. Weinberger` (curly apostrophe in the rendered HTML) silently failed to match against a pattern built from straight-quote lookup keys.
