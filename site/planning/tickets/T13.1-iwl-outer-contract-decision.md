# Evidence basis

T13.0 established:

1. Two outer architectures remain viable:

   * sibling IWL source inside the `research` collection;
   * separate `iwl` collection with a typed parent reference.

2. A flag-only/file-presence design fails because it cannot represent:

```text
ABSENT
SOURCE EXISTS / UNPUBLISHED
SOURCE EXISTS / PUBLISHED
```

3. The current codebase has no source field representing that publication-state distinction.

4. `research-routing.ts` is the canonical Article-routing authority and should remain authoritative.

5. Pagefind currently indexes every generated page body; there is no existing per-page IWL exclusion mechanism.

6. The existing PDF pipeline discovers papers only; IWL does not need to enter it.

7. The current semantic system never projects a standard property automatically; no Article↔IWL JSON-LD relationship has yet been earned.

8. The Chisel Article and IWL fixtures state `CC BY 4.0`, while the live site uses the sitewide `CC BY-NC 4.0` license authority.

9. The real IWL can render as ordinary long-form authored content without parsing its four internal surfaces into schema.

10. The real IWL already expresses the concept of belonging beside one parent Article.

# Decision 1 — Source ownership and parent identity

## Surviving options

### Option A — same `research` collection

```text
research
├── Article
└── IWL
```

Advantages:

* smaller immediate collection surface;
* filesystem co-location;
* reuse of one collection.

Costs:

* Article and IWL become members of the same semantic collection;
* existing Article-oriented schema must accommodate a distinct object class;
* parent validity depends more heavily on convention;
* future IWL schema evolution couples to Article truth.

---

### Option B — separate typed `iwl` collection

```text
research
└── Article

iwl
└── IWL
     └── parent → typed reference → research
```

Advantages:

* Article and IWL remain distinct object classes;
* parent validity can fail closed at build time;
* future IWL schema evolves independently;
* the opaque-body rule maps naturally onto its own collection;
* existing Article schema stays conceptually narrow.

Cost:

* one additional collection and associated discovery logic.

---

## Recommended outcome

**Option B — separate `iwl` collection.**

Recommended contract:

```text
research
→ owns primary Article truth

iwl
→ owns subordinate IWL truth

IWL.parent
→ required typed reference to exactly one research entry
```

The IWL owns the parent association.

The Article must not receive an authored reciprocal IWL identifier.

### Recommended cardinality

```text
one Article
→ zero or one IWL source

one IWL
→ exactly one valid Article parent
```

T13.2 should eventually fail closed on both orphan IWLs and duplicate IWL sources for one parent.

# Decision 2 — Minimal envelope and publication state

## Recommended envelope

```text
IWL
├── parent
├── title
├── publicationState
├── pubDate?
└── authored body
```

No `dateModified` is recommended for Sprint 13.

T13.0 did not establish a concrete outer-publication behavior requiring it. It may be earned later if versioning or public update metadata creates a real need.

---

## `parent`

Recommended:

```text
parent: reference('research')
```

No authored:

```text
URL
category
Article title copy
canonical path
```

is required for identity.

---

## `title`

Recommended as a required authored string.

Rationale:

* the IWL is independently addressable;
* the real fixture has a distinct document identity;
* readers need a page title;
* forcing one universal derived naming pattern has not been earned.

This does not make the IWL a peer scholarly Article.

---

## `publicationState`

Recommended explicit source field:

```text
publicationState:
  unpublished
  |
  published
```

No default.

No inference from:

```text
file existence
Git branch
date
Article state
route
body contents
```

Recommended complete state machine:

```text
NO SOURCE
→ ABSENT

SOURCE + unpublished
→ EXISTS / NOT PUBLIC

SOURCE + published
→ EXISTS / PUBLIC
```

`publicationState` is an outer publication-control field.

It is **not** an inner IWL lifecycle state.

---

## `pubDate`

Recommended:

```text
unpublished
→ optional / may be absent

published
→ required
```

This gives public IWLs an explicit publication date without requiring speculative modification/version fields.

---

## Recommended exclusions from envelope

Do not add:

tags
readerNote
version
dateModified
layer types
node types
edge types
epistemic status
author
ORCID

Author identity and site licensing remain centrally owned unless product authority chooses otherwise.

# Decision 3 — Route and canonical identity

## Recommended route

```text
Article
/research/{category}/{slug}/

IWL
/research/{category}/{slug}/iwl/
```

The IWL route derives from the resolved parent Article canonical path.

Conceptually:

```text
iwlPath(iwl)
=
canonicalPath(parent)
+
"iwl/"
```

Exact helper names remain T13.2 implementation detail.

---

## Recommended routing invariants

No IWL frontmatter contains:

```text
route
slug override
category
canonicalURL
parentURL
```

Existing Article routing truth remains authoritative.

---

## Recommended identity contract

```text
ARTICLE
→ primary scholarly identity

IWL
→ independently addressable web resource
→ own derived canonical URL
→ subordinate to and governed by the parent Article's canonical path
→ not a peer scholarly Article
```

The IWL URL is **not independently stable** from its parent.

If the parent's canonical category or slug changes, the child route changes with it.

That is part of the subordinate identity contract, not drift.

Public IWL existence requires:

```text
valid parent
+
publicationState: published
```

# Decision 4 — Pagefind / internal search

## Evidence

Pagefind currently indexes built pages normally.

Excluding IWL would require adding new machinery.

---

## Recommended outcome

Do not add such machinery in Sprint 13.

Recommended behavior:

```text
ABSENT
→ no page
→ no search result

UNPUBLISHED
→ no route
→ no search result

PUBLISHED
→ built page

```

A published IWL is intended to be inspectable.

If real use later demonstrates that IWL results degrade internal search, exclusion can be separately earned.

## Final Decision Record

Product authority reviewed all eight decisions at the checkpoint following Commit A's seal (`00b9c76`) and accepted every recommended outcome as specified, with no modifications and no rejections. This record appends the approved outcomes; it does not rewrite the recommendation basis sealed in Commit A above.

D1 — Source ownership
Final: **Option B — separate `iwl` collection**, `IWL.parent` a required typed reference to exactly one `research` entry. The IWL owns the parent association; the Article receives no authored reciprocal IWL identifier.
Rationale: preserves Article/IWL object-class separation, fails closed on a dangling parent at build time (matching `validate-research-relation-projections.mjs`'s existing discipline), and keeps future IWL schema evolution decoupled from Article truth.

D2 — Minimal envelope/state
Final: `{ parent, title, publicationState: 'unpublished' | 'published', pubDate? (required iff published), opaque authored body }`. No `dateModified`. Full exclusion list (format, pillar, doi, tags, readerNote, version, layer/node/edge/epistemic-status fields, author, ORCID, affiliation, license, canonicalURL, parentURL) applies exactly as specified.
Rationale: the smallest field set that expresses the three real states (ABSENT / SOURCE-EXISTS-UNPUBLISHED / SOURCE-EXISTS-PUBLISHED) without inference, and without letting any inner-grammar or re-authored-identity field leak into the outer contract.

D3 — Route/identity
Final: `/research/{category}/{slug}/iwl/`, derived as `canonicalPath(parent) + "iwl/"`. No authored route/slug/category/canonicalURL/parentURL in IWL frontmatter. IWL canonical identity is subordinate and parent-governed, not independently stable.
Rationale: extends `research-routing.ts`'s existing single routing authority rather than duplicating it — the same discipline that prevents the kind of hand-authored `canonicalURL` drift this codebase has already fixed once.

D4 — Pagefind
Final: **index normally**. No new exclusion machinery built in Sprint 13. ABSENT/UNPUBLISHED never resolve to a route, so they're never indexed regardless. A published IWL is indexed exactly like every other built page.
Rationale: no per-page opt-out mechanism exists anywhere in this codebase today (confirmed directly in T13.0); building one now would be speculative machinery for a need not yet demonstrated. A published IWL is meant to be inspectable — indexing it is consistent with that intent. Exclusion remains available as a later, separately-earned decision if real use shows it degrades search.

D5 — Human navigation
Final: Article→IWL link renders in the existing `after-title` publication-metadata region (alongside masthead/tags/PDF link), conditionally, only when a published IWL exists for that Article — no new `ArticleShell` slot. IWL→Article carries an explicit "Companion to: `<parent Article title>`" link near the top of the IWL, linking to the parent's canonical route.
Rationale: an IWL is a companion *publication* object, not Reader Context — it belongs in the same seam as the other publication-associated surfaces, not the seam Sprint 12 deliberately reserved for non-metadata orientation content. Absence stays genuine: no link, no disabled state, no placeholder, no reserved spacing.

D6 — Licensing
Final: **published IWL inherits the sitewide `LICENSE` constant (CC BY-NC 4.0)**. No `license` field enters the IWL envelope. No per-object licensing is supported in Sprint 13.
Rationale: explicitly accepted, not deferred. Under this decision, both the Chisel Article's and Chisel IWL's own "CC BY 4.0" text are real drift against the site's already-adopted sitewide license and must be reconciled to CC BY-NC 4.0 before either fixture is ever published — this ticket records that requirement; it does not perform that reconciliation, which belongs to whatever ticket first authorizes Chisel's actual publication.

D7 — Public semantics
Final: **deliberate semantic silence**. No `Article.hasPart`, `IWL.isPartOf`, `citation`, `mentions`, `about`, `subjectOf`, or any other approximate substitute. No research-relation projection row added. The IWL page gets ordinary `BaseHead`-style metadata and Open Graph only — never `Article`/`ScholarlyArticle`/DOI/Highwire/research-relation semantics.
Rationale: matches the `backstory` precedent from Sprint 12 — no "default-on" public-semantic path exists anywhere in this codebase, and no property inspected in T13.0 was a truthful, earned fit for an Article↔IWL relationship yet. The internal typed parent reference plus human navigation are sufficient for the outer contract alone.

D8 — Article integration
Final: the Article remains free of authored IWL metadata (no `iwlId`/`iwlPath`/`iwlUrl`/`hasIwl`). The IWL source alone owns the parent relationship; Article rendering derives at build time whether exactly one published IWL points to itself, and that derived result (not an authored field) controls the D5 navigation link.
Rationale: keeps parent association single-sourced (D1) rather than duplicated across both sides, consistent with this project's standing discipline against hand-duplicated derived facts (the same discipline `categorySegment()`/`canonicalPath()` already enforces for Article routing).

**Recommendations not accepted:** none. All eight decisions were accepted exactly as recommended in Commit A, including D6 (licensing), which required and received explicit approval rather than silent default.
