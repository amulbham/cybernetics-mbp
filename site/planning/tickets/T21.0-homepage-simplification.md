## Goal

Replace the current homepage with a single-column, low-friction research feed: short hero, one hardcoded spotlight, and a chronological recent-publications list. Remove category/pillar blocks from the home page. Preserve existing header navigation, design tokens, footer category navigation, and all research routes.

## Why now

Sprint 19 retired the public “pillar” taxonomy in favor of categories. The homepage still surfaces category cards and the build validator currently requires them. A concise feed better matches the scholarly publisher role. Desk is the next manuscript pilot; once its staging acceptance is recorded it becomes the natural spotlight.

## Starting state

Current homepage renders ordered category cards (asserted by `validate-research-semantics.mjs`). `Spotlight` and `RecentResearch` components already exist. `HOMEPAGE_SPOTLIGHT` constant already exists in `consts.ts`. Research collection is sorted by `pubDate`. No `featured` frontmatter field. Live/staging entries include Desk, Chisel, Invariants, Three SOS, FAFSA, and Frontier Utility. Header already contains Research and About links. Design system uses Atkinson, IBM Plex Mono, Signal tokens, and `--content-width-prose` (720px). RSS discovery link lives in `BaseHead`. Indexing remains closed.

## Decisions already frozen

- Spotlight is the existing `HOMEPAGE_SPOTLIGHT` constant in `consts.ts`, set to `the-desk-is-where-you-write-it-down` (T20.1 staging acceptance is recorded at `0a89656`). No second spotlight constant, no new `featured` schema field. Invalid id fails the build (existing fail-closed behavior).
- No category filter or pillar/category grouping blocks on the homepage.
- Single-column constraint uses `var(--content-width-prose)` (720px) for hero, spotlight, and feed. No Tailwind utilities.
- Chronological feed shows the next five entries after the spotlight (or fewer if the corpus is smaller). Equal `pubDate` values are ordered deterministically by entry id ascending. Feed changes to `RecentResearch` must be opt-in so the 404 page behavior is preserved.
- Summaries for both spotlight and feed use `entry.data.excerpt` only. Do not render the full `description`. Reading time remains optional and is not newly calculated.
- Archive count is the length of the full research collection, not the length of the visible feed.
- “View Full Archive” and any research-index links point at the existing research index route.
- Header navigation is unchanged. Footer category navigation, ORCID, license, and RSS (via `BaseHead`) remain.
- No new design-system primitives. Reuse existing typography, color, and spacing tokens.
- Light/dark and mobile must remain readable.
- Hero copy (literal; **replaces** rev 3's SEO/policy wording per the Product Authority, 2026-10-13):  
  H1: “Research on knowledge, cognition, and complex systems.”  
  Description: “Independent research on how ideas emerge, how systems organize, and how technology and institutions shape the conditions for discovery.”  
  Link: “About the researcher →” to `/about`.  
  The old eyebrow and the two CTA buttons are removed.
- `SITE_DESCRIPTION` in `consts.ts` is set to the approved description above; its propagation to homepage metadata, WebSite JSON-LD and the RSS channel description is authorized. RSS entries, links, dates and feed-generation logic are not touched.
- Spotlight keeps the bordered card (one anchor around the whole card — no nested link), shows a muted category text label instead of the prominent badge, and a visible “Read paper →” affordance (non-link text inside the card anchor).
- Feed: opt-in homepage presentation of `RecentResearch`; default behavior, including the 404 page, is unchanged (compared before/after, ignoring build-generated hashes).
- The validator's homepage category-grid assertion is replaced and a small footer category-order assertion is added; the category-route and route-only-memos checks stay. No homepage testing framework.
- Release ordering: the Desk may be featured on staging now, but T21.0 must not reach production ahead of the Desk's own production publication (an unknown spotlight id fails the build). Desk production promotion and Zenodo coordination stay separate gates; the Desk's confirmed publication date 2026-10-14 is preserved.

## Scope

1. **Hero**  
   Short title and one-sentence description as frozen above. Single text link to `/about`. No category list.

2. **Spotlight**  
   Use the existing `Spotlight` component driven by `HOMEPAGE_SPOTLIGHT`. Bordered card kept; shows a muted category text label, date, title, `excerpt` and a visible “Read paper →” affordance inside the single card anchor (canonical article route; no nested link). No image required.

3. **Recent feed**  
   Use or extend the existing `RecentResearch` component in an opt-in homepage mode. Remaining entries in reverse-chronological order (deterministic id tie-break), limited to five. Each row shows date, category (muted), title, and `excerpt`. Divider lines only; no heavy card chrome. Link each title to its article.

4. **Archive exit**  
   Text link or quiet button to the research index, showing the full collection count.

5. **Validator**  
   Replace the ordered homepage category-card assertion in `validate-research-semantics.mjs` with a small homepage check (no category-grid block; the spotlight's canonical link present) and add one footer category-order assertion (registry order). Retain route checks, memos exclusion, and Person validation. Not a new homepage test framework.

6. **Metadata**  
   Set `SITE_DESCRIPTION` to the approved description so homepage `<meta description>`/Open Graph, WebSite JSON-LD and the RSS channel description agree with the hero; `<title>` stays `Amul Bham`. `BaseHead` needs no change.

8. Footer category navigation, route checks, memos exclusion, and Person validation continue to pass.
