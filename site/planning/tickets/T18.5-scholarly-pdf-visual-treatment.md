## Goal
Turn the existing Vivliostyle paper PDFs into a distinct, readable, scholarly projection with white pages and academic serif typography, retaining all established PDF/HTML identity and information-completeness guarantees.

## Why now
The T18.4 print-clipping defect is corrected and staging CI is green; the current `print-research.css` still forces Signal cream (`#f4f1ea`) and inherits an Atkinson-based screen reading system (20px desktop body). Product Authority approved two complementary scholarly references: **Invariants for compact working-paper density/conventions**, and a **mathematics-paper reference for restrained navy/ochre signature**. Working-paper convention always wins over branding. A 42-page Desk PDF was also inspected for academic typesetting, but is not the sole governing visual reference.

- Vivliostyle typesets the built HTML through `site/scripts/build-research-pdfs.mjs --style print-research.css`; four existing `format: paper` PDFs, no essay/IWL PDF.
- Print CSS fixes Letter paper, 1in margins, title ordering, ORCID continuity and hidden IWL navigation, with `thead th { white-space: normal !important; }` from T18.4.
- T18.4 evidence found all 19 current paper tables complete after the wrap correction. Current staged GitHub Actions workflow run `36947738806` succeeded; no new visual PDF treatment is yet implemented.
- Visual hierarchy: **Invariants = academic density/convention**; **mathematics paper = optional restrained navy/ochre cues**; neither reference authorizes copying problematic narrow-table pagination. The mathematics-paper PDF is not attached to this ticket package; if comparison to its exact pages is material, request that reference before claiming a visual match.

## Implementation contract
- All publication appearance changes must be print-only; the built HTML content and screen reading experience remain unchanged.
- Prefer a close Latin Modern–style serif; if not viable, use another reproducible, appropriately licensed font with Product Authority approval. Document font file provenance/license (if bundled), verify renderer resource loading and embedded font identity in generated PDFs, and inspect glyph fidelity in text layer **and** rendered samples. Computed CSS family alone is insufficient. Never depend solely on an unpinned external web font or local-machine fallback.
- Maintain conventional academic legibility (body roughly 10.5–12pt as a starting heuristic, not a universal pass/fail limit); do not solve layout by shrinking tables/references until unreadable. Preserve long URL/citation break behavior. Inspect for new clipped/overlapped text, stranded headings and empty continuation pages.
- Attempt paged-media `@page` margin boxes/counters for visible, correct page numbers and restrained **short-title/Bham running-header furniture** on body pages. If deriving a real short title from the existing DOM is unsupported, use an honest generic Bham running header instead of inventing manuscript metadata. Inspect multiple pages for repetition, collisions, and first-page behavior. If this cannot work in print CSS alone, stop with rendered evidence and seek explicit Product Authority approval for a documented **running-header deferral**; page numbering remains required unless separately decided. No builder/DOM edit is authorized.
- Do not suppress or rewrite authored text to achieve layout; gracefully handle longer headings, tables, and references by layout, not deletion.
