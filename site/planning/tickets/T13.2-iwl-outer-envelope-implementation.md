## Goal

Implement the minimum outer architecture required for one real IWL to exist safely beside one Article.

The implementation must support:

```text
research collection
└── Article
    └── primary scholarly object

iwl collection
└── IWL
    ├── parent
    ├── title
    ├── publicationState
    ├── pubDate?
    └── opaque authored body
```

with the three required states:

```text
NO SOURCE
→ absent

SOURCE + unpublished
→ exists privately in source
→ not publicly routed

SOURCE + published
→ public subordinate web resource
```

and the frozen relationship:

```text
Article
   │
   │ 0..1
   ▼
IWL
```

# 1. Add the `iwl` collection

Extend `src/content.config.ts` with a distinct `iwl` collection.

Use the installed Astro content-reference mechanism so `parent` is a typed reference to `research`.

Required source contract:

```text
parent
→ required reference('research')

title
→ required trimmed, non-empty string

publicationState
→ required
→ exactly 'unpublished' | 'published'
→ no default

pubDate
→ optional for unpublished
→ required for published

body
→ ordinary Markdown/MDX content
```

Use a strict object schema so unearned outer fields cannot silently enter the architecture.

Do not add:

```text
format
pillar
doi
tags
readerNote
version
dateModified
author
ORCID
affiliation
license
canonicalURL
parentURL
inner IWL fields
```

`AUTHOR` and `LICENSE` remain centrally owned.

### Published-state validation

Fail the build when:

```text
publicationState = published
AND
pubDate is absent
```

An unpublished IWL may have a date, but does not require one.

Do not infer state from the date.

# 2. Preserve parent/cardinality invariants

The implementation must guarantee:

```text
each IWL
→ exactly one valid research parent

each Article
→ at most one IWL source
```

The typed Astro reference should provide fail-closed parent resolution.

Add the smallest additional build-time logic required to reject:

```text
two IWL entries
→ same parent
```

This uniqueness rule applies across **all publication states**, not only published IWLs.

For example:

```text
unpublished IWL A → Article X
published IWL B   → Article X
```

must fail.

Do not weaken this to "one published IWL per Article."

### One registry, not parallel truth

Implement one centralized IWL loader/index helper that:

1. loads the complete `iwl` collection;
2. resolves and validates every parent;
3. enforces one-IWL-source-per-parent across all publication states;
4. exposes the published subset and Article lookup to route and layout consumers.

The IWL route and Article→IWL navigation must consume this same validated result. Do not create independent lookup implementations that could disagree about presence, publication state, or cardinality.

---

# 3. Add one IWL route helper

Extend the existing routing authority rather than creating independent routing truth.

Add the minimum helper equivalent to:

```text
iwlPath(parent)
=
canonicalPath(parent) + "iwl/"
```

Expected result:

```text
parent Article
/research/{category}/{slug}/

child IWL
/research/{category}/{slug}/iwl/
```

Do not modify the behavior of `canonicalPath()` for existing research.

No IWL source may author:

```text
category
slug
route
canonicalURL
parentURL
```

The parent remains the route authority.

---

# 4. Add the subordinate IWL route

Add the Astro route corresponding to:

```text
/research/{category}/{slug}/iwl/
```

The route must generate paths **only for** `publicationState: published`.

Before filtering for public paths, the route/build process must still validate the complete IWL collection so malformed or duplicate unpublished entries cannot hide from validation.

For every public IWL:

1. Resolve its typed parent.
2. Derive category/slug from the parent using existing routing logic.
3. Generate the subordinate route.
4. Render the IWL body.
5. Pass the resolved parent into the IWL layout.

Do not derive public routing from the IWL entry's own file ID.

## Canonical identity

The IWL's canonical page identity must resolve from:

```text

```

not from authored metadata.

If satisfying this requires a page-local canonical link because the existing generic head path cannot accept one cleanly, use the smallest IWL-local solution.

Do not redesign `BaseHead` globally unless existing behavior demonstrably requires it.

# 6. Render parentage explicitly

Near the top of every published IWL, render:

```text
Companion to:
<parent Article title>
```

where the title links to:

```text
canonicalPath(parent)
```

The user must not have to infer parentage from breadcrumbs or URL structure.

Breadcrumbs may reinforce this relationship but do not replace it.

# 7. Add Article → IWL navigation

Update `ResearchLayout.astro` so a research Article can derive whether exactly one **published** IWL points to it.

The Article must remain free of authored reciprocal metadata.

Do not add:

```text
hasIwl
iwlId
iwlUrl
iwlPath
```

to research frontmatter.

Instead:

```text
IWL sources
        ↓
build-time lookup
        ↓
published IWL for current Article?
        ↓
YES → render link
NO  → render absolutely nothing
```

Place the link in the existing `after-title` publication-metadata area, as frozen by T13.1.

The current `after-title` area already owns masthead/tags/PDF publication material.

Do not create a new ArticleShell slot.

### Absence rule

For:

```text
no IWL
```

or:

```text
unpublished IWL
```

there must be:

```text
no link
no wrapper
no placeholder
no reserved spacing
```

# 8. Preserve normal Pagefind behavior

Do not add Pagefind configuration.

The behavior should emerge from routing:

```text
ABSENT
→ no route
→ not indexed

UNPUBLISHED
→ no route
→ not indexed

PUBLISHED
→ real page
→ ordinary Pagefind indexing
```

No `data-pagefind-ignore`.

No special collection filtering.

No search-specific architecture.

Do not change sitemap, robots, or external-indexing controls. A published IWL follows the site's existing generic public-route behavior; absent and unpublished IWLs produce no route to discover. Any special inclusion or exclusion mechanism requires separate authority.

# 11. Licensing

IWL rendering must consume the existing sitewide `LICENSE` authority.

Do not add per-IWL license source data.

Current product decision:

```text

```

Any publication candidate derived from the Chisel fixture must have its existing `CC BY 4.0` body text reconciled before it can be marked published.

Do not silently publish contradictory license declarations.

The rendered page must have one licensing authority. Prefer removing the fixture-local license declaration during the approved content conversion and rendering the canonical sitewide license through the layout. Do not hard-code a second copy of `CC BY-NC 4.0` into the opaque body merely to make the strings agree.

# Acceptance criteria

T13.2 closes only when:

1. `iwl` is a distinct content collection.
2. `parent` is a required typed reference to `research`.
3. `title` is required.
4. `publicationState` is required and has no default.
5. `pubDate` is required iff published.
6. No unearned envelope field is accepted.
7. IWL body remains opaque content.
8. A dangling parent fails closed.
9. Two IWL sources for one parent fail closed regardless of publication state.
10. Public routes are generated only for published IWLs.
11. IWL route derives from parent routing truth.
12. No IWL-authored route/canonical/parent URL exists.
13. Published IWL has its own derived canonical web URL.
14. IWL remains a non-Article object class.
15. IWL page explicitly links to its parent.
16. Article conditionally links to a published IWL in the existing after-title area.
17. Absent/unpublished states produce genuine Article-link absence.
18. Research frontmatter gains no reciprocal IWL field.
19. Published IWL uses normal Pagefind behavior.
20. No Pagefind opt-out, sitemap special-case, robots change, or external-indexing control is introduced.
21. No Article↔IWL JSON-LD relation is introduced.
22. No IWL PDF behavior is introduced.
23. IWL rendering uses the sitewide CC BY-NC license authority.
24. No inner IWL grammar is formalized.
25. Synthetic implementation probes are reverted.
26. One explicitly approved Chisel Article/IWL pair is integrated on staging; otherwise this criterion fails and T13.2 remains open at the paired publication-candidate checkpoint.
27. The exact approved candidate versions and SHA-256 content hashes are recorded.
28. The rendered Chisel IWL exposes one canonical sitewide license authority and no conflicting fixture-local declaration.
29. Existing Article/Reader Context/semantic/PDF behavior shows no regression.
30. Staging deployment is green.
31. T13.2 closure unlocks only drafting/sealing T13.3.

# Stop conditions

Stop rather than widen T13.2 if:

- implementing the frozen contract requires changing Article canonical identity;
- typed references cannot provide the required parent guarantee without a different architecture;
- uniqueness cannot be enforced without redefining source ownership;
- Pagefind needs special handling for basic correctness;
- IWL rendering requires parsing its internal semantic surfaces;
- Article semantics must be changed merely to render navigation;
- a public JSON-LD relation becomes necessary;
- PDF architecture must change;
- the paired Chisel Article/IWL staging candidates are not explicitly approved;
- integrating the Chisel parent Article requires weakening or expanding the existing research-object contract;
- license drift remains unresolved at the point publication is requested;
- an implementation finding requires changing a T13.1 frozen decision.

A contradiction with a frozen decision returns to planning authority; it does not get patched around.
