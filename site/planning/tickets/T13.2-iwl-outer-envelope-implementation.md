## Goal

Implement the minimum outer architecture required for one real IWL to exist safely beside one Article.

The implementation must support:

```text
research collection
└── Article
    └── primary scholarly object

iwl collection
└── IWL
    ├── parent
    ├── title
    ├── publicationState
    ├── pubDate?
    └── opaque authored body
```

with the three required states:

```text
NO SOURCE
→ absent

SOURCE + unpublished
→ exists privately in source
→ not publicly routed

SOURCE + published
→ public subordinate web resource
```

and the frozen relationship:

```text
Article
   │
   │ 0..1
   ▼
IWL
```

# 1. Add the `iwl` collection

Extend `src/content.config.ts` with a distinct `iwl` collection.

Use the installed Astro content-reference mechanism so `parent` is a typed reference to `research`.

Required source contract:

```text
parent
→ required reference('research')

title
→ required trimmed, non-empty string

publicationState
→ required
→ exactly 'unpublished' | 'published'
→ no default

pubDate
→ optional for unpublished
→ required for published

body
→ ordinary Markdown/MDX content
```

Use a strict object schema so unearned outer fields cannot silently enter the architecture.

Do not add:

```text
format
pillar
doi
tags
readerNote
version
dateModified
author
ORCID
affiliation
license
canonicalURL
parentURL
inner IWL fields
```

`AUTHOR` and `LICENSE` remain centrally owned.

### Published-state validation

Fail the build when:

```text
publicationState = published
AND
pubDate is absent
```

An unpublished IWL may have a date, but does not require one.

Do not infer state from the date.

# 2. Preserve parent/cardinality invariants

The implementation must guarantee:

```text
each IWL
→ exactly one valid research parent

each Article
→ at most one IWL source
```

The typed Astro reference should provide fail-closed parent resolution.

Add the smallest additional build-time logic required to reject:

```text
two IWL entries
→ same parent
```

This uniqueness rule applies across **all publication states**, not only published IWLs.

For example:

```text
unpublished IWL A → Article X
published IWL B   → Article X
```

must fail.

Do not weaken this to "one published IWL per Article."

### One registry, not parallel truth

Implement one centralized IWL loader/index helper that:

1. loads the complete `iwl` collection;
2. resolves and validates every parent;
3. enforces one-IWL-source-per-parent across all publication states;
4. exposes the published subset and Article lookup to route and layout consumers.

The IWL route and Article→IWL navigation must consume this same validated result. Do not create independent lookup implementations that could disagree about presence, publication state, or cardinality.

```text

```

Do not modify the behavior of `canonicalPath()` for existing research.

No IWL source may author:

```text

```

The parent remains the route authority.

# 4. Add the subordinate IWL route

Add the Astro route corresponding to:

```text
/research/{category}/{slug}/iwl/
```

The route must generate paths **only for** `publicationState: published`.

Before filtering for public paths, the route/build process must still validate the complete IWL collection so malformed or duplicate unpublished entries cannot hide from validation.

For every public IWL:

1. Resolve its typed parent.
2. Derive category/slug from the parent using existing routing logic.
3. Generate the subordinate route.
4. Render the IWL body.
5. Pass the resolved parent into the IWL layout.

Do not derive public routing from the IWL entry's own file ID.

## Schema/envelope implemented

`parent: reference('research')` (required) · `title: string` (required) · `publicationState: 'unpublished' | 'published'` (required, no default) · `pubDate` (required iff published, via `.refine()`) · `.strict()`. Matches T13.1's Final Decision Record exactly — no additional field.

## Parent/cardinality enforcement

`src/lib/iwl.ts` resolves every parent via `getEntry()` (defensive fail-closed on top of Astro's own content-reference validation pass, which fires first and independently) and enforces one-IWL-source-per-parent across the *complete* collection before any `publicationState` filtering — proven by Probe D (an unpublished + a published entry sharing one parent both fail the build, named explicitly in the diagnostic).

## Route derivation

`iwlPath(parent) = canonicalPath(parent) + 'iwl/'` in `research-routing.ts`. The route file coexists with the sibling `[slug].astro` as an independent Astro route (a dynamic-segment folder and dynamic-segment file of the same name don't collide) — confirmed directly: `/research/ai-systems/the-chisel-fallacy-what-pangram-actually-measures/` and `.../iwl/` both build and both resolve correctly.

## Publication-state behavior

Three states proven via probes A/B (local) and the real fixture (staging): ABSENT/unpublished produce no route and no Article link (probe A); published produces a real route, both navigation links, and normal Pagefind indexing (probe B, confirmed again with real content).
