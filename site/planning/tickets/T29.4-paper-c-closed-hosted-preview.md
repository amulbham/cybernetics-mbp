## Implementation contract
- **Target.** The nonproduction Pages project chosen in D1 (recommended: a new dedicated direct-upload project; the live project is not used). Pages preview environment only; no Git integration, no custom domain, no custom branch alias, no production deployment.
- **Hostnames.** Enumerate and test every reachable hostname class in the pins record §5: each immutable `<hash>.P.pages.dev`, the branch alias, the project's production address `P.pages.dev` (not covered by the preview toggle; must hold no candidate), any custom domain or alias (expected none), and the existing live hosts (must not serve Paper C).
- **Authentication.** Cloudflare Access application for `*.P.pages.dev`, one Allow policy with only the owner's explicit email(s), no Everyone, bypass or domain include, owner-completable login, owner-set session; policy verified by the canary before sensitive bytes exist. Authenticated verification by D3-A (short-lived service token through the session credential form, never in chat) or D3-B (owner-run kit). Credentials are never written to Git, logs or the report.
- **Anonymous denial.** No cookies or custom headers; GET and HEAD on `/`, the route, the route PDF, `/robots.txt`, `/sitemap-index.xml`, one `/_astro/*` asset and `/canary.txt`; plus `Range: bytes=0-15` on the PDF; redirects followed. Pass only for 302 to a `*.cloudflareaccess.com` login or 401/403. Fail on 200, 206 or 304, `application/pdf`, `Content-Range`, a `%PDF-` or candidate-marker body, or a final destination other than the login page. Rows with no Access cover (production address, existing hosts) must return 404 for the route and PDF.
- **Authenticated check.** All seven PDFs fresh-downloaded through the authenticated path and hashed against §2 of the pins record (six historical plus the candidate); every non-HTML inventory file hashed against the TSV; HTML compared after the known Cloudflare normalizations; `X-Robots-Tag: noindex, nofollow` on every response; robots Disallow; the route absent from the sitemap.
- **Captures.** Ordered full-article captures at 1440 px and 390 px of the served route, with the immutable URL, branch alias, correction tree, candidate PDF hash and timestamp in the index; masthead, abstract, four Key findings, scholarly tables and horizontal-scroll behavior, callouts, citation links, author note, DOI presentation and the "Download candidate PDF" link; keyboard focus and in-page anchors.
- **Failure behavior.** Any denial miss, hash or digest mismatch, unexpected hostname, Access misconfiguration, or an unauthorized upload target: stop, contain (replace the branch's latest deployment with a neutral one, then delete the candidate deployment with `wrangler pages deployment delete <id> --project-name <P> --force`, since the latest deployment of a branch cannot be deleted), verify the immutable hostname is denied or gone, and return.
