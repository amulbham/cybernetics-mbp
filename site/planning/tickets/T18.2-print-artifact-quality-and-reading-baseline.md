## Goal

Fix the two earned scholarly-PDF presentation defects from T18.0, establish a repeatable targeted PDF-QA method, decide whether the ORCID defect earns a stable mechanical check, and record a bounded factual baseline of the current long-form HTML reading system for the later Reader-PR phase. Not a redesign and not the table-mechanics ticket.

## Why now

T18.0 found both defects on the live corpus: the masthead ORCID breaks after its last hyphen on page 1 of all four PDFs, and Chisel's page 1 opens with the screen-only `Intellectual Work Ledger` link ahead of the title. Identity work is complete and promoted, so print quality is the next earned step.

## Starting state

- Print CSS hides screen chrome by a whole-element list that omits `.iwl-link`. The title block is a flex column that orders `h1`, subtitle, masthead, date; unordered children sort first.
- `ArticleMasthead.astro` prints a literal `orcid.org/0009-0009-7660-4031` while its href reads `SOCIAL_LINKS.orcid`; `AuthorNote.astro` already derives its label from `SOCIAL_LINKS.orcid`.
- Baseline reproduced 2026-09-29 on unmodified source: page-1 ORCID split `…0009-0009-` / `7660-4031` in all four; Chisel page 1 starts `Intellectual Work Ledger`.

## Decisions already frozen

PDF identity, redirect, Highwire, JSON-LD, and canonical contracts (T18.1). `AuthorNote` ships in the PDF. Indexing stays closed. `SOCIAL_LINKS.orcid` is the ORCID source.

## Questions this ticket may answer

- Does first-page masthead ORCID continuity earn an `AUTOMATABLE STABLE INVARIANT`, or is targeting brittle?
- What are the measured desktop and mobile reading properties of one representative paper?

## Scope

**A — Fixes.** (1) Masthead ORCID text derived from `SOCIAL_LINKS.orcid`, kept unbroken in print only, by a print-scoped rule. Screen rendering unchanged. (2) `.iwl-link` omitted from print output by adding it to the print hide list. Screen Article↔IWL navigation unchanged.

**B — Targeted QA.** Rebuild all four PDFs. Inspect first and last page of each: title hierarchy, subtitle, masthead, ORCID continuity, date placement, title hyphenation; last-page clipping, stranded content, author-note ending. Chisel must not begin with the IWL link. This is not a full pagination review. Extractable text is not evidence of visual correctness.

**C — ORCID validator experiment.** Expected value derived from `SOCIAL_LINKS.orcid`. Inspect only the page-1 masthead region; a later `AuthorNote` ORCID must not satisfy it. Whitespace/newline behavior must not be normalized so far that a split ORCID passes. Must fail on the saved broken baseline PDFs and pass on all four fixed PDFs. If targeting is brittle or renderer-dependent, do not add it; record why and keep continuity as manual QA.

**D — Reading baseline (measurement only).** One representative paper, selected and justified. Measure at 1440px and 390px after web fonts load: typeface plus fallback, size, line-height, prose measure, paragraph spacing, alignment, heading rhythm, colors, normal-prose contrast ratio in each theme where the pair changes, mobile/desktop shell differences, TOC/chrome behavior, JS dependence of core reading. Record any more canonical design-system width as an observation. Classify findings ACCESSIBILITY REQUIREMENT (≥4.5:1), EVIDENCE-BACKED HEURISTIC (~60–70ch, ~1.5–1.65 leading, flush-left, protected column), or DESIGN CHOICE. Heuristic ranges are Reader-PR input, not pass/fail. Written to `planning/audits/T18.2-long-form-reading-baseline.md`.
