## Goal

1. Verify staging has no mobile viewport regression relative to production.
2. Quiet the `FromTheAuthor` visual treatment.
3. Re-run the same mobile measurements after the change to prove the polish itself introduced nothing new.

## Why now

Pre-`T12.2` gate, not a new Reader Context feature slice: the semantic-projection decision in `T12.2` builds on top of the surface `T12.1` shipped, so any visual or regression debt in that surface should be resolved first, cleanly, before more is layered on it.

## Starting state

Verified at ticket authorization:

- Production (`amulbham.com`) has no `T12.1` Reader Context work at all — Sprint 12 has shipped to `staging` only.
- Staging (`staging.cybernetics-mbp-site.pages.dev`) has `FromTheAuthor.astro` live on Invariants and Three SOS, with `T12.1`'s original treatment: `border-top`/`border-bottom`, `var(--text-primary)` on the `why` paragraph, mixed padding/margin.
- FAFSA carries no `readerNote` on either branch — the intended control fixture, since any difference found there is necessarily unrelated to `FromTheAuthor`.

## Decisions already frozen (not reopened by this ticket)

- The title `<hr>` stays the universal publication-metadata → reading-flow seam; `FromTheAuthor` must not redefine that shell contract to solve visual line density.
- No `ArticleShell.astro` changes — polish is scoped to `FromTheAuthor.astro`'s own `<style>` block only.
- Existing Signal tokens only (`--border`, `--text-primary`, `--text-secondary`, `--space-*`, `.meta`) — no new token, no new color, no icon, no avatar, no box, no accent stripe.
- The explicit `{' '}` whitespace fix between the `for` label and its audience string (`T12.1`) stays exactly as-is.

## Questions this ticket may answer

- Does staging actually differ from production on the control fixture (FAFSA) at any tested width? (If yes: stop — that's a pre-existing regression unrelated to Reader Context, to diagnose before touching any CSS.)
- Is `.from-the-author` actually contained within `.prose` at every tested width, or does it overflow?

## Scope

- Real headless-Chrome viewport measurement (reusing the Chrome binary Vivliostyle already downloads, via `puppeteer-core` — the same tool/method Sprint 10 established for viewport work) against the **live** `amulbham.com` (production) and `staging.cybernetics-mbp-site.pages.dev` (staging) URLs directly, at four viewports: 375×812, 390×844, 430×932, 768×1024 (tablet).
- Fixtures: FAFSA (control, on both branches) and Invariants (Reader Context, staging only) as the two required pages; Three SOS as a phone-width spot-check only.
- Per page/viewport, record: `window.innerWidth`, `document.documentElement.clientWidth`/`scrollWidth`, `document.body.scrollWidth`, `window.visualViewport?.width`, and bounding rects for `main`, `.article-body`, `.prose`, `.from-the-author` (where present), `[data-toc-mobile]`, `header`.
- Scan all visible elements for `getBoundingClientRect().right > innerWidth + 1` or `.left < -1`; report the exact selector and rect before changing any CSS.
- **If and only if** the containment/control checks pass, apply the visual polish — scoped entirely to `FromTheAuthor.astro`'s own `<style>` block.

## Explicit exclusions

- `ArticleShell.astro` — untouched.
- The title `<hr>` — untouched.
- Any new decoration: background wash, left accent bar, border, box-shadow, radius, icon, avatar, narrower max-width, new color, new token.
- Any change to `readerNote` content, schema, eligibility, TOC membership, PDF exclusion, `AuthorNote`, `ArticleMasthead`, relation registries, JSON-LD, or `validate-research-semantics.mjs`.

## Implementation contract

If the containment/control checks pass, `FromTheAuthor.astro`'s `<style>` block changes to:

- Remove `border-top`/`border-bottom` (and the padding/margin values that existed alongside them) — the component is distinguished by label, type hierarchy, and secondary ink alone, not framing.
- `.from-the-author-why`/`.from-the-author-for`: `color: var(--text-secondary)`, `font-size: var(--text-base)` (16px) — explicitly **not** `--text-sm` (14px), since the article body reads at ~20px and `--text-base` already creates a clear secondary hierarchy without pushing real orientation prose into fine-print/metadata territory on a phone.
- Preserve the label hierarchy (`.meta`, uppercase, the inline `for` label) and the existing `{' '}` whitespace fix exactly.

Absence/failure behavior: if the control fixture (FAFSA) shows any difference between production and staging, stop before touching CSS — the regression, if any, is not `FromTheAuthor`'s to fix under this ticket.

## Acceptance criteria

- FAFSA geometrically equivalent between production and staging at all four viewports: same `innerWidth`, same key element rects, same horizontal-scroll state. Vertical height may differ only if unrelated content differs.
- `.from-the-author` fully contained within `.prose` on Invariants (and, spot-checked, Three SOS) at all four viewports, both before and after the CSS polish.
- `document.documentElement.scrollWidth <= window.innerWidth + 1` everywhere, both branches, before and after.
- Post-polish, the reading hierarchy is visibly quieter than body/title/Abstract — not resembling a second navigation bar or a card.
