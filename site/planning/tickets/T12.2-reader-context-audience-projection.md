## Goal

Implement the smallest truthful machine-readable projection of Reader Context:

```text
readerNote.for
    → exact, authored projection
Article.audience
    └── @type: Audience
        audienceType: <readerNote.for verbatim>

readerNote.why
    →
human surface only
    └── no Article.backstory
```

The same change must migrate `validate-research-semantics.mjs` atomically from "all Reader Context semantics are forbidden" to an independent source-to-output oracle that requires exactly this asymmetric contract.

## Why now

`T12.1` established the optional, strict, complete-or-absent `readerNote` source model and its `FromTheAuthor` human surface. `T12.1.1` verified and polished that surface. The current emitted semantic graph still forbids both `audience` and `backstory`, so the human and machine contracts are intentionally separated at the exact decision point this ticket owns.

The official Schema.org definitions were rechecked during planning on 2026-09-14:

- [`audience`](https://schema.org/audience) describes the intended group for whom a `CreativeWork` was created and expects an `Audience` value.
- [`Audience`](https://schema.org/Audience) is the intended audience for an item.
- [`audienceType`](https://schema.org/audienceType) accepts `Text` describing the target group.
- [`backstory`](https://schema.org/backstory) is framed for an `Article`, typically a `NewsArticle`, and emphasizes why/how it was created in a reporting or journalistic-process context.

`readerNote.for` is already an authored statement of the group for whom the work was created, so the `audience` mapping is direct. `readerNote.why` records intellectual motivation, not consistently a reporting-process or methods backstory, so projecting it would be approximate. Under the existing semantic-graph rule, approximation resolves to silence.

This ticket makes no SEO, ranking, rich-result, indexing, or discovery claim. It is a truthfulness and machine-legibility change only.

## Decisions already frozen

1. **Ship only `readerNote.for → Article.audience`.** The exact shape is:

   ```json
   {
     "audience": {
       "@type": "Audience",
       "audienceType": "<the authored readerNote.for string verbatim>"
     }
   }
   ```

2. **Do not project `readerNote.why`.** `Article.backstory` remains absent on every research object, including objects that carry Reader Context.
3. `readerNote` remains the sole authored source. Do not add `audience`, `audienceType`, `backstory`, or another semantic field to frontmatter.
4. Projection is governed solely by `readerNote` presence, never by `format`, `pillar`, voice, tags, DOI, relation state, or runtime inference.
5. The `audienceType` string is emitted verbatim. Do not summarize, classify, split, normalize, rewrite, tokenize, or infer a shorter audience label.
6. A missing `readerNote` produces no `audience` property at all — never `null`, `[]`, `{}`, or an inferred fallback.
7. One complete `readerNote` produces one `Audience` object, not an array.
8. The `Audience` object contains exactly `@type` and `audienceType`. It receives no `@id`, `name`, URL, inferred taxonomy, or additional properties.
9. This is a source-field projection, not a research-relation projection. It must not use or modify `research-relation-projections.json`, `PROJECTION_PROPERTIES`, relation types, or relation serializers.
10. Reader Context remains HTML-visible and PDF-hidden. This ticket changes no human-facing presentation.
11. `audience` is not evidence of indexing, search ranking, Google Scholar eligibility, or a supported Google rich result.

## Adversarial tests

Perform all mutations after a valid local build. Use temporary, uncommitted edits and restore them before final validation.

1. **Missing required projection**
   - Remove `audience` from Invariants' built Article JSON-LD.
   - Run `npm run validate:semantics`.
   - Expected: non-zero; diagnostic identifies missing expected `Article.audience` for Invariants.

2. **Source/output string drift**
   - Change Invariants' built `audience.audienceType` to a unique sentinel.
   - Run `npm run validate:semantics`.
   - Expected: non-zero; diagnostic reports exact mismatch against `readerNote.for`.

3. **Unauthorized projection on an absent source**
   - Add a plausible `Audience` object to FAFSA's built Article JSON-LD.
   - Run `npm run validate:semantics`.
   - Expected: non-zero; diagnostic says `audience` is present although the source has no `readerNote`.

4. **Malformed or expanded object shape**
   - Add an unauthorized extra property to Three SOS's built `Audience` object, then separately test a wrong/missing `@type` if the first mutation does not already exercise that branch.
   - Run `npm run validate:semantics` for each required branch.
   - Expected: non-zero; exact-shape/type failure.

5. **Forbidden `why` projection**
   - Add `backstory` to Invariants' built Article JSON-LD using its real `readerNote.why` text.
   - Run `npm run validate:semantics`.
   - Expected: non-zero; `backstory` remains explicitly unauthorized even when the value looks plausible.

6. **Source-driven positive control**
   - Temporarily change one existing `readerNote.for` value to a unique sentinel in source and run the full build.
   - Expected: emitted `audienceType` and the independently derived validator expectation both follow the source; no fixture string is hard-coded.
   - Restore the authored value exactly and rebuild.

After all mutations, prove restoration with a clean diff against the intended implementation and rerun the full local validation chain.
