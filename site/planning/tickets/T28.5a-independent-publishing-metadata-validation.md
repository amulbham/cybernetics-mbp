## Required design proposal for Executor, reviewed before coding
- Introduce **one independently owner-approved expectations fixture** for a narrow set of facts: canonical Person name/`@id`, known ORCID/selected verified `sameAs` destinations, expected About `jobTitle` and source-approved profile revision date (or absence), site license, approved per-entry DOI and publication/revision dates. Keep site source and expected-values definitions **distinct**. No importing `personIdentity()`, `AUTHOR` or frontmatter to *construct* the expected facts under test.
- Explicitly mark entries whose intended values remain **owner decisions** (Paper A DOI three occurrences, true `dateModified`, final role, About `dateCreated` provenance). **Two-phase executable rollout (reviewer R1/R2):** phase **BASELINE** pins *currently deployed* observable values and must **PASS on a clean rebuild of pinned main** before any of T28.1–3. At baseline, About `ProfilePage.dateModified` is a **narrow documented legacy exception**: its value changes at build time. Validate it only as a syntactically valid timestamp in the **About ProfilePage field**, not a fixed expected instant; **never** grant this exception to paper dates, other page timestamps or unrelated fields. About legacy `dateCreated: 2026-08-01T00:00:00Z` must be recorded as **observed but provenance UNVERIFIED**, not endorsed as factual. All other already-grounded facts are checked precisely. Require clean baseline CI PASS and an adversarial test proving that unrelated wrong dates still FAIL. Phase **TARGET** removes the About dateModified legacy exception entirely, expecting **absence** unless an exact, evidenced, separately approved About revision date is recorded; it likewise expects `dateCreated` absent unless substantiated. Full **exact-set equality** on canonical Person `sameAs` (normalized only for well-defined URL equivalence, not silent deletion): fail on **extra, missing, duplicate, substituted or malformed** URLs, including lingering Substack. The approved A1/A2/A3, role/bio and Substack changes transition with matching fixture edits in their **ticket-owned commits**, not by importing production helpers. Paper A substantive revision date remains absent. Record baseline vs target oracle identities explicitly; no source parser may silently rewrite A2.
- Add a post-build checker (tentative `site/scripts/validate-publishing-facts.mjs`) comparing HTML/JSON-LD/Highwire/visible output and independent **human-reviewed** fixture (tentative `site/scripts/fixtures/publishing-facts.json`). Assert `headline` vs visible title, author identity, DOI, dates (including true absence), license and `og:image` file existence in `dist`. **Explicitly authorize modifying only the `site/package.json` normal `build` script** to invoke the checker **after `astro build` and before completion of the build pipeline**. This is the hook both production and staging GitHub Actions already run via `npm run build`; no direct workflow changes are needed for this CI hook. It must **exit nonzero on target contract mismatch**. Do not add a bypass env flag or silently swallow failures. Distinguish build-local image existence from live remote reachability. Any package-lock effect requires explanation; no unrelated workflow edits.
- Keep existing relation, semantic and PDF validators in place; avoid copying whole serializers or expanding into general network crawling. A factual oracle stored alongside code still requires **human review of oracle edits**; it does not independently prove current real-world facts.
- Pin Google Scholar metadata expectations for `format: paper` and negative tests for essays, with no journal/affiliation fabrication. All six PDFs must remain frozen.
