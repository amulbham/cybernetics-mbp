## Goal and rationale
Close audit **F2 REQUIRED**: a build can agree with itself while asserting an incorrect author, DOI, date, license, identity destination, About title or image. Of **36** scratch adversarial mutations, 17/27 emitted-HTML cases and 2/9 source-level cases were caught. The other probes escaped. Build/source agreement must not be mistaken for factual correctness.

## Required design proposal for Executor, reviewed before coding
- Introduce **one independently owner-approved expectations fixture** for a narrow set of facts: canonical Person name/`@id`, known ORCID/selected verified `sameAs` destinations, expected About `jobTitle` and source-approved profile revision date (or absence), site license, approved per-entry DOI and publication/revision dates. Keep site source and expected-values definitions **distinct**. No importing `personIdentity()`, `AUTHOR` or frontmatter to *construct* the expected facts under test.
- Explicitly mark entries whose intended values remain **owner decisions** (Paper A DOI three occurrences, true `dateModified`, final role, About `dateCreated` provenance). Initial oracle may record the currently approved **production** facts and must be updated only in the same separately approved owner decision and review as any T28.1–3 change. A new validator must not lock unresolved *proposals* as truth.
- Add a post-build checker comparing HTML/JSON-LD/Highwire/visible output and the independent facts where meaningful. Assert `headline` vs visible title, author identity, DOI, dates (including true absence), license and `og:image` path exists in generated `dist`. Distinguish canonical external image URL existence at runtime from build-local asset existence. Keep scope to emitted invariants, not speculative rich-result guarantees.
- Keep existing relation, semantic and PDF validators in place; avoid copying whole serializers or expanding into general network crawling. A factual oracle stored alongside code still requires **human review of oracle edits**; it does not independently prove current real-world facts.
- Pin Google Scholar metadata expectations for `format: paper` and negative tests for essays, with no journal/affiliation fabrication. All six PDFs must remain frozen.

## Evidence and adversarial tests
- Reproduce at least the highest-value **source-level** escaped cases from T28.5: wrong author name, wrong social-profile URL, wrong DOI, false pubDate/dateModified, wrong license and About jobTitle; assert **CAUGHT** where a corresponding owner-approved fact exists.
- Reproduce output-level escaped cases: wrong `datePublished`/`dateModified`, `headline` mismatch, removed/nonexistent `og:image`, malformed `sameAs`. Report **caught / escaped / untested**, before and after, for each fixture. Include legitimate `sameAs` removal after author-approved T28.3 to avoid false positives.
- Test that a **permitted real change** fails until the independent approved fixture is updated and then passes, showing both fail-closed drift protection and safe governance.
- All mutation fixtures in disposable copies; tracked changes limited to validator, narrowly approved expectations and tests. No changes to production source fields unless separately authorized.

Actual pre/post release needs the owner-approved **six-path manifest** and SHA checks; `expected.txt` alone is not the manifest.

No `main` push, PDF manifest mutation, Zenodo changes or Google Search Console actions without separate Product Authority release approval.
