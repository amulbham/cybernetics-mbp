# T28.5 — Google Search structured-data and schema-integrity audit

**DRAFT / READ-ONLY / NOT SEALED** · Risk: R2 audit; any follow-up production fix separately authorized.
**Purpose:** Verify that the site's *actual* Schema.org JSON-LD emission, metadata, author identities, crawl behavior and source→HTML→live validator chain remain correct under current official Google Search Central guidance; **not** a schema-property-maximization exercise.

## Structural decision path to audit
`site/src/content.config.ts` frontmatter class `format` → `site/src/layouts/ResearchLayout.astro` editorial mapping: paper `@type: ['ScholarlyArticle','Article']`, essay/memo `@type: 'Article'`; every article has author/publisher canonical `Person` from `site/src/lib/structured-data.ts`, dates, description, image, license, canonical, OG, and optional DOI/MediaObject. About emits `ProfilePage` and enriched `Person` jobTitle. The homepage emits `Person` + `WebSite`. Relations and audience only from separately approved source registry, not text inference.

## Required tests
1. **Corpus and representative pages:** *The Lab Bubble* (essay; Article, no Scholar/PDF claims), *Cognition as a Self-Organizing System* (paper; Article+ScholarlyArticle, PDF+Highwire), Paper A (outdated v1 DOI), Three SOS (cross-reference), About/homepage and one canonical category/tag page. Expand to full corpus if any discrepancy emerges. Record exact commit and source anchors.
2. Cross-check served HTML `<script type="application/ld+json">` against: canonical URL; page title; visible byline/role; OG and visible dates; `datePublished` vs actual original `pubDate`; `dateModified` vs author-approved revision (NOT build timestamp); `license`; actual article class; valid image URL; DOI and `citation_doi` (paper only); media `contentUrl` and downloadable PDF where applicable; single canonical Person `@id`/url/sameAs. Check intent of `publisher=author Person` against site's direct self-publication model.
3. Use official [Google Article structured data](https://developers.google.com/search/docs/appearance/structured-data/article), [general policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies), and [testing tools](https://developers.google.com/search/docs/appearance/structured-data). Distinguish **Schema Markup Validator** (generic Schema.org), **Rich Results Test** (Google-supported feature eligibility), **Search Console URL Inspection** (Google-indexed/rendered view), and independent raw HTML source. Passing one is **not** passing all, and Google does not guarantee a rich result.
4. Inspect declared `image`: generated OG asset must be valid, crawlable, and actually representative; evaluate Google's recommended image dimensions/aspect ratios without automatically manufacturing media. Audit `Person.sameAs` after Substack retirement, About `jobTitle` consistency, About's current **`dateModified: new Date().toISOString()`** build-derived drift, and inaccurate homepage/site description if author role changes.
5. Re-run/inspect code validators: `validate-research-relation-projections`, `validate-research-links`, `validate-research-semantics`, `validate-indexing`, `validate:pdfs`. Identify independent vs self-referential oracles (notably `validate-research-semantics.mjs` imports `personIdentity()` as expected Person core, which ensures parity but not factual correctness). Test a few deliberate *temporary fixture mutations* in isolated tests (wrong type, DOI, fake date, wrong author `sameAs`, inaccessible image/canonical) to confirm failures; restore afterwards. Never mutate live files just to test.
6. Confirm Cloudflare production vs `*.pages.dev` indexing boundaries; production robots/sitemap and individual noindex, canonical on staging. If live Google Search Console is unavailable, report exactly that; don't claim indexing is proven from build logs.
7. For all findings report **source declaration → expected JSON-LD → built HTML → observed live HTML → external validator outcome → classification**, with date and official reference.

## Output / gates
One auditable finding matrix for paper, essay, profile/home and catalog; PASS/FAIL/UNVERIFIED classifications; prioritized BLOCKER/REQUIRED/OPTIONAL deltas and recommended smallest independent remediation tickets. **No source edits, schema expansion, meta tag insertion, new SEO claim, PDF mutation or deployment authorized by this audit.**
