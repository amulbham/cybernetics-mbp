# T28.5 — Google Search structured-data and schema-integrity audit

**DRAFT / READ-ONLY / NOT SEALED** · Risk: R2 audit; any follow-up production fix separately authorized.
**Purpose:** Verify that the site's *actual* Schema.org JSON-LD emission, metadata, author identities, crawl behavior and source→HTML→live validator chain remain correct under current official Google Search Central guidance; **not** a schema-property-maximization exercise.

## Structural decision path to audit
`site/src/content.config.ts` frontmatter class `format` → `site/src/layouts/ResearchLayout.astro` editorial mapping: paper `@type: ['ScholarlyArticle','Article']`, essay/memo `@type: 'Article'`; every article has author/publisher canonical `Person` from `site/src/lib/structured-data.ts`, dates, description, image, license, canonical, OG, and optional DOI/MediaObject. About emits `ProfilePage` and enriched `Person` jobTitle. The homepage emits `Person` + `WebSite`. Relations and audience only from separately approved source registry, not text inference.

## Required tests
1. **Corpus and representative pages:** *The Lab Bubble* (essay; Article, no Scholar/PDF claims), *Cognition as a Self-Organizing System* (paper; Article+ScholarlyArticle, PDF+Highwire), Paper A (outdated v1 DOI), Three SOS (cross-reference), About/homepage and one canonical category/tag page. Expand to full corpus if any discrepancy emerges. Record exact commit and source anchors.
2. Cross-check served HTML `<script type="application/ld+json">` against: canonical URL; page title; visible byline/role; OG and visible dates; `datePublished` vs actual original `pubDate`; `dateModified` vs author-approved revision (NOT build timestamp); `license`; actual article class; valid image URL; DOI and `citation_doi` (paper only); media `contentUrl` and downloadable PDF where applicable; single canonical Person `@id`/url/sameAs. Check intent of `publisher=author Person` against site's direct self-publication model.
3. Use official [Google Article structured data](https://developers.google.com/search/docs/appearance/structured-data/article), [general policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies), and [testing tools](https://developers.google.com/search/docs/appearance/structured-data). For **each checked page/property**, label the source as **site invariant**, **Google recommendation** (check applicability by page type; inapplicable is NOT automatic failure), or **external observation**. Distinguish **Schema Markup Validator** (generic Schema.org), **Rich Results Test** (Google-supported feature eligibility), **Search Console URL Inspection** (indexed/rendered view), and raw HTML source. Passing one is **not** passing all; Google does not guarantee rich results. (Reviewer O1.)
4. Inspect declared `image`: generated OG asset must be valid, crawlable, and actually representative; evaluate Google's recommended image dimensions/aspect ratios without automatically manufacturing media. Audit `Person.sameAs` after Substack retirement, About `jobTitle` consistency, About's current **`dateModified: new Date().toISOString()`** build-derived drift, and inaccurate homepage/site description if author role changes.
5. Re-run/inspect code validators: `validate-research-relation-projections`, `validate-research-links`, `validate-research-semantics`, `validate-indexing`, `validate:pdfs`. Identify independent vs self-referential oracles: `validate-research-semantics.mjs` imports production `personIdentity()` as its expected Person core, which tests parity, **not factual correctness**. Independently derive owner-approved name/role/identity URL/ORCID/LinkedIn/other `sameAs` from an explicit fact-and-destination checklist **outside production `personIdentity()`**. Use **disposable untracked fixtures in a scratch/worktree test environment**, never mutate tracked source or live records, for deliberate wrong article type, bad DOI, false revision date, wrong `sameAs`, inaccessible image and canonical. Record **caught / escaped / untested** (with reproduction/evidence) for each; an escaped mutation is a **measured coverage gap**, not grounds to claim audit failure or auto-change the production validator. Any validator changes are a separately scoped authorized ticket. (Reviewer R4.)
6. Confirm Cloudflare production vs `*.pages.dev` indexing boundaries; production robots/sitemap and individual noindex, canonical on staging. If live Google Search Console is unavailable, report exactly that; don't claim indexing is proven from build logs.
7. For all findings report **source declaration → independently grounded expected JSON-LD/metadata (owner-approved facts) → built HTML → observed live HTML → external validator outcome → classification**, with timestamp and official page-type-specific reference. Report validator mutation outcome **caught/escaped/untested** separately from factual correctness and Google's indexing/feature eligibility. (Reviewer R4/O1.)

## Output / gates
One auditable finding matrix for paper, essay, profile/home and catalog; **site-invariant vs Google-recommendation vs external-observation** classifications and PASS/FAIL/UNVERIFIED findings; an independent owner-approved identity/destination checklist; per-mutation **caught/escaped/untested** coverage results; prioritized BLOCKER/REQUIRED/OPTIONAL deltas and independently approved remediation tickets only where warranted. **No source edits, schema expansion, meta tag insertion, new SEO claim, PDF mutation or deployment authorized by this audit.**
