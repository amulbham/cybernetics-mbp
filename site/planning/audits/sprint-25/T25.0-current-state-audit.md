## Owner operator guide proposal
Not created as a file, per the boundary. Proposed one-page content (plain language, no SHAs or run numbers, so it does not go stale), each point grounded in M:deploy-pages.yml:25–28, the Planner README and this session:

1. **Branches are labelled shelves in one repository.** `main` = the live website. `staging` = rehearsal copy of the website. `planner/context` = notes, plans and audit reports; it never publishes. A task branch (for example `claude/...` or `review/...`) = one job's draft, safe to discard.
2. **Workspaces are not branches.** A local or cloud workspace is a temporary copy of the repository on some machine. A cloud session starts from a fresh copy and is reclaimed afterward, so anything not committed and pushed is lost.
3. **Four verbs.** Commit = save a snapshot in the copy. Push = upload it to GitHub. Pull request = ask to bring one branch into another. Merge = do it.
4. **What deploys the website.** Only a push to `main` (production) or `staging` (rehearsal), including a merge into either. Opening a PR, pushing a task branch or `planner/context`, or merging into `planner/context` does not deploy.
5. **Agent routine** (no approval each time): fetch, read, edit within the ticket's paths, commit, push to the assigned branch, report evidence. **Amul approves:** scope and seals, staging acceptance, anything going to `main`, repository variables (`PDF_MANIFEST` and friends), indexing, editorial wording, Zenodo and DOI steps.
6. **Starting and finding results.** Start a fresh session on the assigned branch with the role prompt in the [audits README](README.md). Results: the committed file on the branch, the Actions run page, the PR page, the staging alias, then production.
7. **Cloud-first effect.** Cloud work removes copying files between machines: manuscripts can arrive on a branch (or the non-deploying `planner/assets/`), evidence is read through the connector, and the report is a pushed file. Still manual today: setting repository variables (not readable by an agent here), downloading the production PDF for Zenodo, and moving the staging-approved PDF into `release-pdfs/` (T23 did this through a local copy). Whether a cloud container can run the full build and PDF step is untested.

Cloud-first assessment.
