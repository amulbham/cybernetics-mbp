## Responsive tables (`<!-- table-layout: responsive-records -->`)

- Source: exactly three markers, each immediately before an Appendix GFM table (17×4, 4×5, 4×5), one blank line between. `rehype-table-wrap.mjs` consumes the marker (it arrives in the HAST as a `raw` sibling) and emits `.table-container[data-table-layout="responsive-records"]` (no `tabindex`: nothing scrolls) containing the original `<table>` plus a generated `ul.table-records[data-pagefind-ignore]` (`li` → `dl` → `dt` column header / `dd` cloned cell, ids stripped). Unmarked tables take the old code path: **all five other papers render byte-identical HTML under the old and new plugin** (12 + 3 + 2 + 2 tables).
- CSS (`global.css`): records hidden by default (so never in print/PDF); `@media screen and (max-width: 1099px)` hides the table and shows the records — 1100px is the site's own TOC breakpoint. Rendered widths: wrapped table fits with no sideways scroll at 1100 and 1440 (container 718px, 14px type); forced-table measurement at 768/900/1000 also fits, but the contract's tablet rule governs, so records show below 1100.
- Fail-closed (throws; `validate-research-links.mjs` runs the same pipeline): unknown layout, orphan/duplicate marker, duplicate/empty column headers, ragged/colspan/nested shape. A real orphan marker in the Desk source made `validate-research-links` exit 1; restored byte-identically.
